# 设计决策

每条都是「已定」，想推翻先在本页追加新条目，不要悄悄改实现。

## ADR-1 不做拼音

- **结论**：`words` 无 `pinyin` 列，粘贴解析不处理拼音，界面不显示
- **理由**：家长朗读，孩子默写；拼音既帮不上忙，还占录入成本与表结构
- **影响**：打印单只有田字格，没有拼音行
- **修订（2026-11-07，ADR-19）**：「界面不显示」收窄为「除笔画复习页外不显示」；数据模型与导入解析的排除**不变**

## ADR-2 TTS 只预留不实现

- **结论**：`trait Speaker` + `NullSpeaker` 注入 `AppState`，V1 无调用点
- **理由**：将来可能用系统语音读词（届时连遮罩都能去掉），但现在不引入语音依赖与平台差异
- **影响**：V2 只需加实现 + 一条命令 + 前端按钮，不动表结构
- **修订（2026-11-07，ADR-19）**：已按此路径实现系统离线 TTS，命令层与表结构确实没动

## ADR-3 错题本不建表

- **结论**：错题本 ≡ `words.status='learning'`，历史错误靠 `wrong_count` 与 `session_items`
- **理由**：独立错题表必然与词表不同步，删词/改词时会留下孤儿
- **影响**：出本规则必须落在 `word_progress.rs`；跨表统计走 JOIN

## ADR-4 跨组按词语去重

- **结论**：一场默写里同一 `text` 只抽一次，保留分组顺序靠前的
- **理由**：同一个词在一场里写两遍没有意义，孩子会觉得「怎么又来了」
- **副作用**：分组间进度独立，未被抽到的那条永远是 `new`（可接受）

## ADR-5 默认遮罩 + 自动隐藏

- **结论**：翻到新词先自动显示，`maskSeconds` 秒后自动遮住；点击可重看并重新计时（0 = 一直显示）
- **理由**：家长需要立刻读到词，不该先点一下；孩子又不能长时间看到，所以用「限时展示」
- **影响**：设置项 `maskSeconds`；「不自动隐藏」改名为「一直显示」

## ADR-11 分组用自引用树，不用固定两层

- **结论**：`groups.parent_id` 自引用，层数不限；词条只挂在叶子上（但任何节点都能挂词）
- **理由**：需求是「二年级上册 / 第一单元」，但明年可能变成「语文 / 二上 / 第一单元」，固定两层会立刻不够用；自引用树加上路径计算只多几十行
- **影响**：选父级即选全部子孙（抽题、打印、统计），由 `sampler::expand_group_ids` 统一展开

## ADR-12 调整结构靠拖动，编号跟着位置走

- **结论**：词表左侧树支持 HTML5 拖放，一个 `move_group` 命令搞定「换父级 + 调顺序」；纯数字 `code` 按新位置重排
- **理由**：树一旦可多级，「先删再建再搬词」就成了家长的日常负担；拖动是最短路径。编号是家长看得见的标签，拖完还留着「3、1、2」会像 bug，所以数字编号自动重排，非数字（「上」「一单元」）保持原样——它们通常是用户有意的命名
- **实现**：`repo::groups::move_to(conn, id, parent_id, before_id)`，`before_id = None` 表示排到末尾；一次事务里改 `parent_id` + 同级 `sort_order`（10/20/30…），子树与词条随分组走
- **约束**：不能移到自己或自己的子孙里（`in_subtree` 上溯校验）；前端同样先挡一层，避免给出可落点的反馈再报错

## ADR-13 连字抽词在建会话时一次定序

- **结论**：建会话时的抽词偏好 `chain`（默认关，可在抽题页勾上）。开启后随机抽词不再纯洗牌，改走 `sampler::chain_by_shared_char`：先打散，从随机起点出发，每一步优先从剩余候选里挑一个与上一个词共享至少一个字的；没有同字的就随机挑一个，再从那里继续链
- **理由**：顺序在 `session_items.seq` 里落库，是会话的一部分。「每次点下一个再算」会让中途退出/继续、历史回看、只练本次错词全部要跟着改，而且无法复现。定序一次、之后只读，和现有架构一致
- **取舍**：只要求「有相同的字」，不追求最大重叠——对二年级的词来说共享一个字已经足够形成联想；同批共享词之间仍随机挑，不会每次同一个顺序
- **副作用**：关掉偏好即回到纯洗牌。开启优先级/去重后，链上的词可能被挑掉或换掉，相邻关系会断——同档内仍保持链式相对顺序
- **为什么从设置挪到抽题页**：连字是「这一场怎么排」，跟遮罩时长那种全局默认不是一类；放在抽题页能和优先级、去重一起勾，也避免为了一场临时改全局设置再改回来
- **与 ADR-14 共存**：优先级排序会拆开跨档的连字邻接，同一档内仍是链式顺序——「先练该练的」优先于「顺序好读」

## ADR-6 备份手动、导入合并
- **结论**：只做手动导出 JSON；导入是合并非覆盖
- **理由**：自动滚动备份对家长是黑盒；覆盖导入一次误操作就毁掉全部进度
- **代价**：导入无法「还原到某一时刻」，需要还原只能新建库重导

## ADR-7 打印用 window.print + CSS

- **结论**：`PrintSheet.tsx` 渲染 A4 版面，`window.print()` 唤起系统打印
- **理由**：不引打印插件、不生成 PDF 依赖；WebView2 支持
- **约束**：所有打印相关样式集中在 `index.css` 的 ```media print`

## ADR-8 单连接 + Mutex

- **结论**：整个应用一个 `rusqlite::Connection`，加 `Mutex`
- **理由**：单机单用户，并发量为 0；连接池是负债
- **约束**：命令内不要跨 await 长时间持锁；批量写用事务

## ADR-9 命令薄层

- **结论**：`commands/` 只做参数转换与取锁，业务规则在 `domain/` 与 `repo/`
- **理由**：命令层无法单测（依赖 Tauri State），逻辑放进去就测不到

## ADR-10 错字标记不改变出本粒度

- **结论**：批改可标到「哪个字不会写」，但错题本、出本、统计仍以词条为单位；标错的字只用于复盘高亮和抽题权重（ADR-14）
- **理由**：对一个二年级词来说，「春」写错和「天」写错的学习动作一样——整词重写；细分到字做进度会立刻遇到「写对一次算哪个字对」的语义泥潭
- **实现**：`session_items.wrong_chars` 存下标，批改页/历史详情高亮；`sessions::weak_chars` 聚合出弱字池给抽词排序

## ADR-14 抽词优先级：反复错的字 > 写错过的字 > 新词 > 其余

- **结论**：建会话时 `sessions::prioritize` 做稳定排序，档位依次是「同一个字在 ≥2 个不同词里都标错」→「含标错的字」→「`status='new'`」→「其余已练过的词」；上一场刚写过的词只在同档内往后排
- **理由**：错过的字换个词再遇到，比重写一遍已掌握的词有用；新词没写过，当然优先于复习。只排序不删候选，用户选的题量始终能凑满
- **反复错字为什么单独一档**：同一个字在「轻而易举」和「言而有信」里都错，说明不是某个词不熟，而是这个字没掌握；按**不同词的数量**统计（同一个词错十次仍算 1），否则总写错的词会一直霸占前面
- **实现**：弱字池 `sessions::weak_chars` 从 `session_items.wrong_chars` **跨词**聚合——标错「春天」的「天」，下一场的「天空」「今天」也会提前。整词算错没有字下标，不参与；词条改短后的越界老下标直接丢弃
- **红线**：必须用稳定排序且排在洗牌之后，同档内的随机性全靠这一步保住；优先级只用来排序，不能当过滤条件把低档词直接删掉——真正的取舍只在 ADR-15 的档内挑选里发生（见 [pitfalls.md](./pitfalls.md) 第 15 条）
- **取舍**：与 ADR-13 的连字共存时，跨档的连字邻接可能被打断（同档内仍是链式）——优先级高于连字
- **与 ADR-15 的分工**：先按档取词，档内再做去重取舍；优先级永远先于去重

## ADR-15 同批词尽量不重复用字

- **结论**：题量小于候选数时，同一档内优先挑「和已选词没有共同字」的，凑不满再按原顺序补齐；题量为「全部」或候选不够时不做取舍
- **理由**：一场里反复写同一个字容易变成机械抄写，换字更像真默写。但弱字/新词的优先级不能被去重挤掉，所以取舍只在同档内发生
- **实现**：`sessions::pick_diverse` + `select_in_tier`，字集合复用 `sampler::char_set`；结果保持入参顺序，洗牌与连字的随机性不受影响
- **边界**：跨组重复的词早已按 text 去重（ADR-4），这里只处理「字」重复。与连字的取向相反，二者同时开启时连字邻接会被挑词打断
## ADR-16 手工错字存在 words.wrong_chars，不造假会话

- **结论**：错题本可以手工加词；标的错字写进 `words.wrong_chars`（0005 迁移），与批改产生的 `session_items.wrong_chars` 合并展示、合并进弱字池
- **理由**：家长在作业本上看到错字时没有「会话」可挂。为了记几个字去插一条 `sessions` + `session_items`，历史里会冒出一场只有 1 个词的假默写，统计全被污染
- **代价**：错字有了两个来源，读取端必须并集（`words::load_char_marks`、`sessions::weak_chars`）；改词文本会让老下标失效，所以 `words::update` 在文本变化时清空手工标记
- **不做**：不新增 mistakes / char_marks 表——错题本仍等价于 `status='learning'`（ADR-3），这里只补「字」这一层信息

## ADR-17 跨设备同步用整库快照，不做行级复制

- **结论**：本地 SQLite 永远是唯一主库。用户显式配置自有 MySQL 后，云端只存 `dictation_snapshot` 表的单行（`LONGBLOB` 快照 + `version`）；推送用 `UPDATE ... WHERE id=1 AND version=?` 的 CAS 乐观锁，拉取写 `pending.db`，下次启动由 `db::init` 在打开连接前替换。
- **理由**：`0001_init.sql` 的 4 张表都是自增整数主键，跨机按行合并必撞 id；进度「只增 / 归零」语义用 last-write-wins 会抹掉另一台的成绩；`ON DELETE CASCADE` 还要墓碑，`sessions.config_json` 里的分组 id 跨机无效。整库快照一次绕开全局 ID、事件日志、冲突时钟与离线写队列，且会话历史、设置、错字标记全量保真。
- **取舍**：同一时刻只应有一台设备推进数据；两台都改过时**不自动合并**，弹 `ConfirmModal` 让用户决定是否覆盖（覆盖前自动完整备份）。对「家里两台电脑轮流陪孩子默写」足够。
- **定位**：默认纯离线；只有用户填了自有服务信息才联网，且无账号、无厂商云。不推翻「单机离线」的产品定义，只是把「唯一联网行为」改成「默认唯一联网行为」。
- **边界**：整库恢复是数据目录级操作，不算「改进度」，不违反硬约束 1；但同步绝不能成为业务写入口。凭据绝不进 `settings` 表、绝不回传前端。
- **实现**：`repo/sync.rs` 的 `SnapshotStore` trait（当前 `MysqlStore`，将来可换 HTTP API）、`VACUUM INTO` 快照、`content_hash`、`apply_pending`。详见 [sync.md](./sync.md)

## ADR-18 笔顺数据随包发，不连 CDN

- **结论**：错题本的笔顺动画用 `hanzi-writer` + `hanzi-writer-data`，数据在构建时打成 256 个分片放进 `public/hanzi/`，随安装包分发
- **理由**：默认纯离线是产品定义（ADR-17 的定位段）。hanzi-writer 默认从 jsdelivr 按字取 JSON，等于把「看笔顺」绑在网络上——学校、老家、断网时就废了，还会牵出一条没人预期的联网行为
- **代价**：安装包与安装后体积各增加约 30MB（9574 个字），`vite build` 多一次分片拷贝（有 `.stamp` 跳过机制，只在数据包升级时重做）。换来的是任何情况下都能看笔顺
- **为什么分片而不是一字一文件**：一字一文件是 9574 个文件，构建要多复制近万个 inode（实测 `vite build` 从 20 秒涨到 4 分钟），磁盘按簇对齐后 30MB 会占 47MB。256 片后文件数降到 260，按需加载的粒度仍然够用（一片约 37 字）
- **为什么不用 `document.baseURI` 拼路径**：它带上了当前页面的目录，入口一换就 404；而 dev server 对未知路径返回 index.html + 200，表现成「JSON 解析失败」。改为相对站点根（`import.meta.env.BASE_URL`），见 [pitfalls.md](./pitfalls.md) 第 24 条
- **降级**：取不到数据的字退回静态字形，页面不会空白；非汉字（字母、数字、标点）本来就没有笔顺，直接画字
- **不做**：不做「跟着描红判分」（`writer.quiz()`）——这是桌面应用，家长和孩子用鼠标/触控板描红的体验很差，练写交给纸和田字格

## ADR-19 笔画复习页显示拼音 + 系统离线 TTS 朗读

- **结论**：笔画复习页在田字格上方逐字显示拼音（带调），并用系统离线语音朗读词语；「自动朗读」默认关闭，偏好存后端 `settings.strokeAutoSpeak`（本机偏好，拉取替换时与字号等一样留在本机），设置页与复习页内开关共用同一个值；另有「读一遍」手动按钮。其余页面、打印单、数据模型维持无拼音
- **修订（2026-11-07 当天）**：初版翻词自动读存前端 localStorage 且默认开；按用户要求改为默认关，并把偏好挪进后端 settings，与其它设置一样在设置页统一管理、不随清缓存丢失
- **理由**：该页是孩子对照学习的场景（尤其「先自己写」遮住笔画时，页面本来就不显示词语文字，读音成了唯一线索），拼音有正音价值；这与 ADR-1 排除拼音的「默写场景」不冲突
- **拼音来源**：`pinyin-pro` 纯前端离线转换（内置词典，多音字按词消歧，实测「长大」→ zhǎng dà），整词一次转换后与字符对齐；拼音永不进数据库、导入仍不解析
- **TTS 走系统自带语音**（不引联网引擎，维持默认纯离线）：macOS `say` 子进程（探测 zh 语音，`-v` 指定）、Windows SAPI `ISpVoice`（`EnumTokens("Language=804")` 选中文，`SPF_ASYNC` + `SPF_PURGEBEFORESPEAK`）、Linux `spd-say`。系统没装中文语音时报可操作的中文提示
- **代价**：前端产物增大约 0.3MB（pinyin-pro 词典压缩后进 bundle，实测 609KB/gzip 236KB，本地加载无感）；SAPI 代码无法在 macOS 开发机上运行验证，靠 `cargo check --target x86_64-pc-windows-msvc`（最小检查工程，绕开 tauri 依赖树 ring 的交叉 C 编译问题）+ CI Windows 构建 + 审查兜底
- **接口形状**（沿用 ADR-2 的预留）：`speech/` 里 `Speaker` trait + `SystemSpeaker` 按平台分发；命令 `speak_text` / `stop_speak`（async + `spawn_blocking`）；speak 是「先停上一句再读」的幂等语义，StrictMode 双跑无害

## ADR-20 AI 讲解卡：显式配置的 OpenAI 兼容客户端 + 内容缓存表

- **结论**：错题复习页可按需生成「巧记讲解卡」（部件拆解、口诀、例句、易混字辨析）。AI 服务为 OpenAI 兼容 chat completions（DeepSeek / 智谱 / 硅基流动等任填），配置存数据目录 `.ai-config.json`（0600；凭据不进 `settings` 表，key 原值不回传前端，只回掩码）；生成内容存 `ai_cards` 表（随整库快照同步），按词缓存、生成一次离线复用
- **理由**：「怎么记住这个字」是无法预计算的个性化内容，是 LLM 强项而家长最缺。缓存 + 显式配置让默认安装保持零联网——与 ADR-17 的 MySQL 同步同构：又一个「可选的外挂」，不是产品定位的转向
- **红线**：LLM 只产内容，**永不写学习进度**（`word_progress` 不变，讲解不是进度）；输出必须过 `domain/ai_card.rs::validate`（术语黑名单、例句含目标词、长度上限、无换行）才入库；讲解卡在「先自己写」遮蔽模式下整卡隐藏（口诀=答案提示）；面向孩子的内容层（积木/口诀/例句）与给家长的辨析层分开呈现
- **实现**：`commands/ai.rs` 六命令（生成走「拿锁读词→放锁等 HTTP→拿锁落库」，`MutexGuard` 不跨 await）；`ai/config.rs` + `ai/client.rs`（reqwest rustls，30s 超时，校验失败回喂重试一次）；词文本被编辑时清卡（对齐 ADR-16 清手工错字的先例）；新依赖仅 `reqwest`
- **边界**：Phase 2 在线 TTS（智谱 GLM-TTS 等，`/audio/speech`）将复用同一配置文件与 opt-in 边界，届时另立 ADR-21 修订 ADR-19 的「不引联网引擎」
